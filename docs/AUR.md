# Publishing `backline-audio` to the AUR

Status (2026-11-13): **a draft, not published, not to be published until
Manu has tried the build on his box.** The PKGBUILD follows current main:
`pkgver` is the version in `CMakeLists.txt`'s `project()` (the container
check refuses a mismatch), and the source is the GitHub tarball of the tag
`v$pkgver`. Main has moved on since `v0.4.0` (surfaces, RTP-MIDI with
avahi, the Audio Setup panel) and no new tag exists, so the draft is checked
against main's HEAD with `container-check --local`, in a fresh Arch Linux
container on x86_64 (aarch64 is listed but not built here): every dependency
resolves from Arch's official repositories, the unit tests pass in
`check()`, and namcap shows only the expected notes (below). The release
tarball and its checksum get filled in when Manu tags a release. Publishing
also needs an AUR account with an SSH key, which manuaudio hasn't set up.
The name `backline-audio` was free on the AUR on 2026-11-12.

What changed for main (2026-11-13):

- `avahi` is a dependency: `backline-surfaced` links `libavahi-client` to
  find network surfaces (RTP-MIDI) by mDNS.
- `python` is optional, next to `jq`: `omarchy-backline-setup` edits the
  menu rows and hotkeys with a Python helper.
- Every file in `omarchy/lib/` is installed. `omarchy-backline-src.jq` was
  missing from the install, so `omarchy-backline-src` failed in an installed
  tree; `tests/install-layout-test` now checks every lib file.
- `check()` skips `autolink`, the private-PipeWire proof: it is a developer
  proof, and a build chroot has no session for it.
- Paths checked in the package: user units in `/usr/lib/systemd/user`
  (`backline-surfaced.service` enabled in `default.target.wants`), surface
  profiles in `/usr/share/backline/surfaces`, D-Bus activation files in
  `/usr/share/dbus-1/services`, the pacman hook in `/usr/share/libalpm/hooks`.

## The steps (once)

1. **Make the account.** Sign up at <https://aur.archlinux.org/register>
   with the user name `manuaudio` and an email address you read.
2. **Make an SSH key just for the AUR** on the computer you publish from:

   ```sh
   ssh-keygen -t ed25519 -f ~/.ssh/aur -C "manuaudio AUR"
   ```

   and tell SSH to use it for the AUR, in `~/.ssh/config`:

   ```
   Host aur.archlinux.org
     IdentityFile ~/.ssh/aur
     User aur
   ```

3. **Give the AUR the public key.** Paste the contents of `~/.ssh/aur.pub`
   into *My Account → SSH Public Key* on the AUR site and save. Check it with
   `ssh aur@aur.archlinux.org help` (it lists commands instead of "Permission
   denied").

## The steps (each release)

From a checkout of this repository at the release tag:

```sh
packaging/arch/container-check              # builds and lints in a clean container; must end with the file list
                                            # (before the tag exists: --local, which builds HEAD)
git clone ssh://aur@aur.archlinux.org/backline-audio.git /tmp/aur-backline-audio   # empty the first time: that creates the package
cp packaging/arch/PKGBUILD packaging/arch/backline-audio.install packaging/arch/.SRCINFO /tmp/aur-backline-audio/
cd /tmp/aur-backline-audio
git add PKGBUILD backline-audio.install .SRCINFO
git commit -m "backline-audio 0.4.0-1"
git push origin master
```

The package page is then <https://aur.archlinux.org/packages/backline-audio>,
and `yay -S backline-audio` works for everyone.

For the next release: raise `pkgver` (and reset `pkgrel=1`) in
`packaging/arch/PKGBUILD` after the tag exists, run `updpkgsums
packaging/arch/PKGBUILD` (or the container check, which prints the new
checksum), regenerate `.SRCINFO` (`makepkg --printsrcinfo >
packaging/arch/.SRCINFO`; with `--local`, the container's copy in
`packaging/arch/out/` describes the local tarball, not the release), commit them here, and repeat the steps above.

## namcap notes (expected)

- `Directory (var/lib/backline) is empty`: on purpose; the pacman hook
  touches a stamp there after plugin installs (registry rescan).
- `libbackline.so.0 is an uninstalled dependency`: the library is in this
  same package.
- `Dependency included, but may not be needed ('pipewire')`: the services
  need the PipeWire daemon at run time, which no binary links.
- `Referenced library 'python3' is an uninstalled dependency` and
  `Dependency python detected but optional`: only `omarchy-backline-setup`
  needs it, and Omarchy has it.
- `Referenced library 'bash' is an uninstalled dependency` next to
  `Dependency included, but may not be needed ('bash')`: namcap's two
  checks disagree about the scripts' shebang; `bash` stays a dependency.
- The `-debug` package's build-id symlinks point into the main package;
  that is how Arch's split debug packages are made.
